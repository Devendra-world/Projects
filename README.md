# CampusTrace — College Lost & Found

CampusTrace is a professional full-stack PHP + MySQL web application for college students to report lost items, post found items, search campus reports, submit ownership claims, and manage returns.

## Highlights

- Modern responsive dark UI with glassmorphism, gradients and animated micro-interactions.
- Three.js 3D animated hero on the home page.
- Multi-page PHP architecture.
- MySQL database with foreign keys and useful indexes.
- Secure PDO prepared statements.
- Password hashing with `password_hash()` / `password_verify()`.
- CSRF protection on state-changing forms.
- Server-side + client-side form validation.
- Image upload validation: JPG, PNG, WEBP, max 5 MB.
- Lost/found browsing with keyword, type, category, location and date filters.
- Item lifecycle: open → matched/returned/archived.
- Claim workflow with private verification details.
- Notifications table and claim notifications.
- Student dashboard and profile management.
- Admin console for report moderation.
- Mobile navigation and responsive layouts.

## Technology

- PHP 8.1+ recommended
- MySQL 8.0+ / MariaDB 10.6+
- HTML5 / CSS3
- Vanilla JavaScript
- Three.js loaded from jsDelivr CDN (the rest of the UI works without Three.js if the CDN is unavailable)
- PDO for database access

## Local installation — XAMPP / WAMP

1. Install XAMPP or another PHP + MySQL environment.
2. Copy the entire project folder into your web root, for example:
   - XAMPP: `C:\xampp\htdocs\campus_lost_found`
   - WAMP: `C:\wamp64\www\campus_lost_found`

   **Important:** if you copy the _contents_ of the project directly into `C:\wamp64\www`, the site will run at `http://localhost/`. If you keep the `campus_lost_found` folder, use `http://localhost/campus_lost_found/`. Do not mix the two URL styles.

3. Start Apache and MySQL.
4. Open phpMyAdmin.
5. Import `database/schema.sql`.
6. Open `config/db.php` and confirm:

```php
$dbHost = '127.0.0.1';
$dbName = 'campustrace_db';
$dbUser = 'root';
$dbPass = '';
```

Change these values if your MySQL installation uses a password or another database host.

7. `BASE_URL` is now detected automatically from the WAMP/Apache document root. This fixes the common problem where the HTML loads but CSS/JS do not load. You normally do not need to edit it.

8. Ensure `assets/img/uploads/` is writable by PHP.
9. Visit:

```text
http://localhost/campus_lost_found/
```

## User flow

### Student registration

A student provides name, email, student ID and college. The password is stored as a secure password hash.

### Post lost/found item

A logged-in student selects Lost or Found, adds category, title, location, date, description and optional identifying information/photo.

### Browse and search

Students can filter reports by:

- Lost / Found
- Category
- Location
- Date
- Free-text keywords

### Claim

A student opens an active report and submits a claim. The claim includes a public-facing explanation plus optional proof details. The original poster can approve or reject the claim.

When a claim is approved, the item is marked `returned` and other pending claims on that item are rejected.

## Validation and security

The application includes:

- PDO prepared statements instead of interpolated SQL.
- CSRF tokens for POST forms.
- Password hashing.
- Session regeneration after login.
- MIME detection for uploads using `finfo`.
- Upload size limits.
- Extension generated by detected MIME type.
- Output escaping with `htmlspecialchars`.
- Server-side validation even when JavaScript is disabled.
- Admin authorization checks.
- Ownership checks for item editing and moderation.
- Database foreign keys and unique claim constraint.

## Production checklist

Before deploying publicly:

1. Replace demo admin credentials.
2. Set strong MySQL credentials and move secrets outside the public web root when possible.
3. Set `display_errors=Off` in production and log errors securely.
4. Serve through HTTPS.
5. Configure secure session cookies (`Secure`, `HttpOnly`, `SameSite=Lax/Strict`).
6. Add rate limiting to login and claim endpoints.
7. Add email verification/password reset if required by your college.
8. Consider malware/image scanning for uploads.
9. Configure web-server rules so PHP cannot execute inside the upload directory.
10. Add automated database backups.
11. Review privacy/data-retention requirements of your institution.
12. Replace the demo seed records with real onboarding data.
